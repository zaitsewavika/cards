# Инструкции репозитория Cards

## Контекст проекта

- Cards — настольный веб-помощник на React и TypeScript для учёта карт в игре «Дурак».
- Это не самостоятельная карточная игра. Не реализовывать игроков, руки, ходы, колоду добора или правила игры, если требования проекта не изменены явно.
- Считать `instructions/README.md` индексом задач, а `instructions/00-architecture.md` — основным источником архитектурных решений.

## Работа с задачами из каталога `instructions`

- Перед выполнением нумерованной задачи полностью прочитать её Markdown-файл и проверить все указанные зависимости.
- Выполнять задачи по порядку номеров и не выходить за рамки текущей задачи; не переносить в неё возможности из последующих задач.
- Перед завершением задачи выполнить её критерии приёмки и указанные команды проверки.
- При противоречии требований приоритет имеют: текущий запрос пользователя, затем файл нумерованной задачи, затем `instructions/00-architecture.md`.

## Инженерные соглашения

- Сохранять строгие настройки TypeScript. Не отключать правила компилятора или линтера ради подавления ошибок.
- Сохранять доменную логику и редьюсер чистыми и независимыми от React, CSS, DOM и `localStorage`.
- Обновлять состояние неизменяемо, а данные представления вычислять селекторами вместо дублирования доменного состояния.
- Использовать CSS Modules для стилей компонентов, а `src/styles/global.css` — только для общих стилей приложения.
- Не добавлять библиотеку интерфейса, маршрутизацию, библиотеку состояния или рабочую зависимость без явного разрешения.
- Не добавлять в коммиты сгенерированные или локальные артефакты: `node_modules`, `dist` и файлы журналов.

## Документация

- Вести всю документацию проекта только на русском языке.
- Новые и изменяемые Markdown-файлы, описания архитектуры, инструкции и комментарии документационного характера писать на русском языке.
- Не переводить имена файлов, команды, идентификаторы, названия технологий и фрагменты кода, для которых важно точное написание.

## Проверка

- После изменения исходного кода выполнять `npm run lint` и `npm run build`.
- После появления тестов также выполнять `npm run test -- --run`.
- Сообщать о каждой невыполненной проверке и указывать причину.

## Git и внешние действия

- Для выполнения каждой задачи создавать отдельную ветку от актуальной основной ветки до начала изменений.
- После завершения задачи и успешных проверок создавать осмысленный коммит, отправлять ветку на GitHub и открывать отдельный PR в основную ветку.
- Не выполнять автоматическое слияние PR. Оставлять решение о слиянии пользователю.
- Все операции платформы GitHub, включая работу с репозиториями, PR, задачами и проверками, выполнять только через GitHub CLI `gh`. Не использовать GitHub-коннекторы, веб-интерфейс или прямые вызовы API.
- Для локальных операций с ветками и коммитами, а также для отправки и получения изменений использовать `git`.
- Не выполнять публикацию или развёртывание и не изменять другие внешние сервисы без явного запроса пользователя.
- Сохранять посторонние изменения пользователя и добавлять в индекс только файлы, относящиеся к текущей задаче.
