# Архитектура проекта Cards

## 1. Назначение

Cards — одностраничный веб-помощник для игрока в онлайн-«Дурака». Пользователь держит приложение открытым рядом с игровой страницей и отмечает карты, которые ушли в бито. Цель — быстро видеть, какие карты ещё не вышли из игры.

Это не реализация правил «Дурака» и не самостоятельная карточная игра. Приложение не знает игроков, руки, колоду добора и ходы. Оно ведёт только список отмеченных карт.

## 2. Зафиксированные требования MVP

- Целевая платформа: современный браузер на ПК.
- Колода: ровно 36 карт, достоинства от шестёрки до туза.
- Порядок строк сверху вниз: `6`, `7`, `8`, `9`, `10`, валет, дама, король, туз.
- В каждой строке отображаются все четыре масти одного достоинства.
- Пользователь выбирает козырную масть.
- Столбец выбранной козырной масти всегда перемещается в крайнее правое положение.
- Нажатие на карту помечает её как ушедшую в бито.
- Повторное нажатие возвращает карту в список оставшихся.
- Кнопка «Отменить» отменяет последнее изменение.
- Кнопка «Новая партия» сбрасывает отмеченные карты после подтверждения.
- Состояние автоматически сохраняется в `localStorage` и восстанавливается после случайного обновления страницы.
- Карты создаются средствами HTML/CSS, но визуально должны напоминать реальные игральные карты.

## 3. Технологические решения

- React и TypeScript.
- Vite как dev-сервер и сборщик.
- CSS Modules для стилей компонентов либо обычные локально именованные CSS-классы; не смешивать оба подхода без причины.
- React `useReducer` для переходов состояния.
- React Context, Redux, Zustand и сервер не нужны для MVP.
- `localStorage` для одного локального состояния партии.
- Vitest и React Testing Library для тестов.

## 5. Модель предметной области

```ts
export const SUITS = ['clubs', 'diamonds', 'hearts', 'spades'] as const;
export const RANKS = ['6', '7', '8', '9', '10', 'jack', 'queen', 'king', 'ace'] as const;

export type Suit = (typeof SUITS)[number];
export type Rank = (typeof RANKS)[number];
export type CardId = `${Suit}-${Rank}`;

export interface Card {
  id: CardId;
  suit: Suit;
  rank: Rank;
}
```

Колода генерируется декартовым произведением `RANKS × SUITS`. Порядок массива `RANKS` является единственным источником порядка строк.

Отображаемые подписи, символы и цвета не должны храниться в состоянии партии. Их следует получать из статических словарей:

- `clubs → ♣`, `diamonds → ♦`, `hearts → ♥`, `spades → ♠`;
- `jack → В`, `queen → Д`, `king → К`, `ace → Т`;
- черви и бубны — красные, трефы и пики — чёрные.

## 6. Состояние и переходы

```ts
interface GameSnapshot {
  discardedIds: CardId[];
  trumpSuit: Suit;
}

interface GameState extends GameSnapshot {
  history: GameSnapshot[];
}
```

Рекомендуемые действия:

```ts
type GameAction =
  | { type: 'toggle-card'; cardId: CardId }
  | { type: 'set-trump'; suit: Suit }
  | { type: 'undo' }
  | { type: 'reset' }
  | { type: 'hydrate'; snapshot: GameSnapshot };
```

Перед `toggle-card` и `set-trump` текущее состояние добавляется в `history`. `undo` восстанавливает последний снимок. `reset` очищает отмеченные карты; выбранную масть можно сохранять либо возвращать к начальному значению — для MVP следует возвращать к заранее документированному значению, например `spades`.

Reducer должен быть чистой функцией: без `localStorage`, таймеров и обращения к DOM.

## 7. Раскладка и козырная масть

`GameBoard` строит девять строк. Каждая строка соответствует одному элементу `RANKS`.

Порядок мастей вычисляется селектором:

```ts
const orderedSuits = [
  ...SUITS.filter((suit) => suit !== trumpSuit),
  trumpSuit,
];
```

Таким образом, выбранная масть всегда последняя справа. Нельзя переставлять сами карты в состоянии или создавать разные колоды для разных козырей: меняется только представление.

Чтобы столбцы визуально не «прыгали», ширина карты и промежутки фиксируются CSS-переменными. Рядом с правым столбцом можно показать метку «Козырь» и лёгкое выделение фона, не уменьшая читаемость карты.

## 8. Визуальная модель карты

Карточка реализуется как настоящий `<button type="button">` с пропорциями примерно `5:7`.

Внутри:

- достоинство и символ масти в левом верхнем углу;
- крупный символ масти в центре;
- при достаточном размере зеркальный индекс в правом нижнем углу;
- белый фон, тонкая рамка, скругление и небольшая тень.

Состояние «в бито» обозначается одновременно несколькими признаками: сниженная непрозрачность, диагональная линия или крест и изменение рамки. Одного изменения цвета недостаточно.

## 9. Сохранение

Ключ: `cards-game-state:v1`.

Сохранять нужно только сериализуемый `GameSnapshot`, без истории. После перезагрузки пользователь получает актуальные отмеченные карты и козырь, но история отмены начинается заново. Это делает формат стабильнее и исключает бесконечный рост записи.

При чтении необходимо проверить:

- значение является объектом;
- `discardedIds` — массив известных уникальных `CardId`;
- `trumpSuit` входит в `SUITS`;
- неизвестные или повреждённые данные не ломают запуск приложения.

## 10. Поток данных

```text
localStorage -> usePersistedGame -> App/useReducer
                                  |
                                  +-> TrumpSelector
                                  +-> GameStatus
                                  +-> GameBoard -> Card
                                  +-> GameControls

действие пользователя -> dispatch -> reducer -> новое состояние -> localStorage
```

Состоянием владеет `App` или специализированный хук `usePersistedGame`. Дочерние компоненты получают только необходимые значения и обработчики через props.

## 11. Доступность и производительность

- Все интерактивные элементы доступны с клавиатуры.
- У карты есть понятный `aria-label` и `aria-pressed`.
- Фокус заметен визуально.
- Красный и чёрный текст имеют достаточный контраст.
- Анимации короткие и отключаются при `prefers-reduced-motion`.
- Для 36 карт не нужны виртуализация, мемоизация всего дерева или отдельное хранилище состояния.

## 12. Границы MVP

Не входят в первую версию:

- регистрация и синхронизация между устройствами;
- управление руками игроков и колодой добора;
- автоматическое распознавание карт на другом сайте;
- реализация правил игры;
- статистика нескольких партий;
- мобильный интерфейс как отдельный продукт.

## 13. Критерий готовности проекта

Проект готов, когда на настольном браузере пользователь может выбрать козырь, увидеть девять строк карт в правильном порядке, отметить и вернуть любую карту, отменить действие, безопасно начать новую партию и восстановить состояние после обновления страницы. Lint, тесты и production-сборка проходят без ошибок.
