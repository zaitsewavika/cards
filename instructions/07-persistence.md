# Задача 07. Сохранить партию после обновления страницы

## Цель

Гарантировать восстановление отмеченных карт и козырной масти после случайного обновления или закрытия вкладки.

## Зависимости

- Выполнены задачи 01–06.

## Что сделать

1. Создать `src/shared/storage.ts`.
2. Объявить ключ `cards-game-state:v1`.
3. Реализовать функцию сохранения только `GameSnapshot`:
   - `discardedIds`;
   - `trumpSuit`.
4. Не сохранять `history`.
5. Реализовать безопасное чтение с `try/catch` вокруг JSON parsing и операций Storage.
6. Валидировать загруженные данные:
   - объект не `null`;
   - масть входит в `SUITS`;
   - список содержит только известные `CardId`;
   - дубли удаляются либо всё значение отклоняется — решение зафиксировать тестом.
7. Создать `usePersistedGame` либо разместить тонкую интеграцию рядом с `App`:
   - лениво загрузить снимок при инициализации;
   - сохранять после каждого релевантного изменения;
   - не записывать некорректное промежуточное состояние.
8. При ошибке чтения запустить чистую партию без падения приложения.
9. После «Новой партии» записать чистый снимок или удалить ключ; выбрать один последовательный вариант.
10. Добавить в README объяснение, что данные хранятся только в текущем браузере.

## Важные сценарии

- Отметить несколько карт, обновить страницу — отметки восстановились.
- Сменить козырь, обновить страницу — козырь восстановился и остался справа.
- Повредить JSON вручную — приложение стартует с чистым состоянием.
- После обновления история отмены пуста; это ожидаемое поведение.

## Критерии приёмки

- Случайный `F5` не теряет текущую партию.
- Ошибка или запрет `localStorage` не делает приложение неработоспособным.
- Формат имеет явную версию в ключе.
- В хранилище нет производных данных и истории.
- Lint и build проходят.
