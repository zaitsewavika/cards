# Задача 09. Покрыть критическую логику тестами

## Цель

Защитить основные сценарии приложения от регрессий и сделать дальнейшие изменения безопасными.

## Зависимости

- Выполнены задачи 01–08.

## Что сделать

1. Подключить Vitest, jsdom и React Testing Library совместимо с Vite.
2. Добавить команды `test` и при необходимости `test:watch` в `package.json`.
3. Настроить общий setup для DOM matcher-ов.
4. Написать тест модели колоды:
   - ровно 36 карт;
   - 36 уникальных ID;
   - девять достоинств по четыре масти;
   - правильный порядок достоинств.
5. Написать тесты reducer:
   - отметка карты;
   - возврат повторным действием;
   - undo после отметки;
   - undo после возврата;
   - безопасный undo без истории;
   - смена козыря;
   - reset;
   - hydrate с пустой историей.
6. Написать тест селектора: козырь всегда последний, остальные масти не теряются.
7. Написать тест `Card`:
   - корректная подпись;
   - `aria-pressed`;
   - вызов обработчика.
8. Написать интеграционный тест `GameBoard`:
   - 36 кнопок карт;
   - строки идут от 6 до туза;
   - козырь расположен в последнем столбце.
9. Написать тесты storage:
   - валидный снимок;
   - повреждённый JSON;
   - неизвестная масть;
   - неизвестные и повторные ID;
   - ошибка доступа к Storage.
10. Добавить один пользовательский сценарий: отметить карту, увидеть изменение счётчика, отменить действие.

## Принципы тестирования

- Проверять наблюдаемое поведение, а не внутреннюю структуру компонентов.
- Использовать доступные роли и имена элементов.
- Не привязывать тесты к случайным CSS-классам.
- Не гнаться за 100% покрытия; критична игровая логика и сохранение.

## Критерии приёмки

- Тесты детерминированы и не зависят от порядка запуска.
- Нет предупреждений React `act`.
- Критические сценарии покрыты.
- Все команды проходят:

```bash
npm run lint
npm run test -- --run
npm run build
```
